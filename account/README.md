# Account — Личный кабинет

Плагин добавляет регистрацию, авторизацию и профиль пользователя на ваш сайт.

## Возможности

- **Регистрация:** email, имя, телефон, пароль (bcrypt)
- **Вход:** email + пароль, Remember-me (cookie 30 дней)
- **Подтверждение email:** ссылка в письме, аккаунт неактивен до подтверждения (по желанию)
- **Восстановление доступа:** magic-link на email (одноразовый токен)
- **Смена пароля:** для авторизованных пользователей
- **Профиль:** просмотр и редактирование имени, телефона
- **Twig-функции:** `is_logged_in()`, `current_user()`

## Маршруты

| Путь | Действие |
|------|----------|
| `/register` | Регистрация |
| `/login` | Вход |
| `/account/forgot` | Восстановление доступа |
| `/account/reset?token=***` | Вход по magic-link |
| `/account/confirm?token=***` | Подтверждение email |
| `/profile` | Профиль |
| `/account/change-password` | Смена пароля |
| `/logout` | Выход |

## Настройки

- `require_email_confirm` — требовать подтверждение email при регистрации (по умолчанию выкл.)
- `default_role` — роль по умолчанию для новых пользователей
- `reset_token_ttl` — срок действия magic-link (1ч / 24ч / 7д)

## Таблицы

- `users` — пользователи
- `user_tokens` — токены (remember-me, password-reset)

## Требования

- apidcms >= 1.0.0
- Настроенная почта (`email_driver`, `email_from_*`) для magic-link

## Безопасность

- Пароли хешируются bcrypt
- Токены: 64 символа (random_bytes), одноразовые
- Rate-limit: один активный токен восстановления на email
- Универсальные сообщения (не раскрывают существование email)

## Хуки

| Хук | Тип | Когда |
|-----|-----|-------|
| `account.registered` | action | аккаунт создан и сразу активен (подтверждение выключено) |
| `account.confirmed` | action | почта подтверждена, аккаунт стал `active` |

## Подтверждение email

Включается настройкой `require_email_confirm`. Значение хранится в `plugin_settings`
(ядро 2.7+), поэтому обновление плагина не меняет поведение сайта.

Требуется настроенная почта (`system_settings`: `email_driver` = `api` или `smtp`,
`email_from_email`). Без неё пользователь останется в статусе `pending` и не сможет
войти — включайте настройку только там, где письма реально уходят.

## Возврат после входа

`/login?return=/subscribe/pro` и `/register?return=/subscribe/pro` — после успешного
входа пользователь попадёт на указанный путь. Принимаются только локальные пути
(начинающиеся с `/`, без `//`) — внешние адреса отбрасываются.
