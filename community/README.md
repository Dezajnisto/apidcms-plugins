# Сообщество — форум, комментарии и сообщества

Один плагин apidcms, который закрывает три задачи: обычный форум, комментарии
к страницам сайта и закрытые сообщества. Всё это — один набор таблиц и один
код, потому что у них общая сущность: **тема с сообщениями**.

## Как устроено

Идея взята у `rainlab/forum-plugin` для OctoberCMS: тема — обычная запись,
у которой есть поле `embed_code`.

| `embed_code` | Что это значит |
|---|---|
| пусто | обычная тема форума: живёт в разделе, её создал пользователь |
| `page:12` | тема привязана к странице сайта и работает как комментарии к ней |
| `item:posts:7` | тема привязана к записи блога |
| `item:catalog:2` | тема привязана к записи любого раздела (каталог, товары) |

Поэтому комментарии не требуют ни отдельных таблиц, ни отдельного кода:
это те же сообщения, что и в форуме, только в скрытом служебном канале.
Модерация, ответы, цитаты, подписка на ответы, пагинация — общие.

Каналы (`channels`) делятся по режиму:

| `mode` | Что | Кто создаёт темы | Где видно |
|---|---|---|---|
| `forum` | раздел форума | пользователи | `/forum/<slug>` |
| `comments` | служебный канал для страниц | автоматически, при первом комментарии | под текстом страницы |
| `community` | сообщество (закрытое или по заявке) | участники | `/community/<slug>` — фаза 2 |

## Установка

1. Скопировать каталог `community` в `public_html/plugins/`.
2. В `plugin.json` поставить `"enabled": true` (или включить в админке).
3. Открыть любую страницу сайта — миграции создадут таблицы и три канала
   по умолчанию (`news`, `help`, `comments`).
4. В админке → Плагины → Сообщество задать адрес форума и правила комментариев.

Плагин не требует ядро новее 2.8.0 и не требует плагина `account`.
Если `account` установлен — форум и сообщества работают для вошедших
пользователей. Если нет — остаются гостевые комментарии с модерацией.

## Что видит посетитель

- `/forum` — список разделов;
- `/forum/<раздел>` — темы, закреплённые сверху;
- `/forum/<раздел>/new` — новая тема (только для вошедших);
- `/forum/<раздел>/<тема>` — сообщения, ответы, форма ответа;
- под статьёй — блок «Комментарии» с формой.

Адрес форума меняется настройкой `forum_prefix` (по умолчанию `forum`).

## Комментарии к страницам

Блок добавляется сам: плагин ловит хук `front.render` и дописывает HTML
в конец `page.content` (или `post.content`, `item.content`). Так комментарии
оказываются под текстом статьи, а не после подвала, и шаблоны тем править
не нужно.

**Если шаблон темы не печатает текст записи** (карточка каталога грузит текст
отдельным запросом, товар собирается из полей), дописывать некуда — тогда блок
ставится перед `</main>` на хуке `front.output`. Маркер `<!--apc-comments-->`
не даёт вставить его дважды. Настройка `comments_position`:

| Значение | Поведение |
|---|---|
| `auto` (по умолчанию) | в тексте статьи, а если его нет — в конце страницы |
| `content` | только в тексте статьи |
| `end` | всегда в конце страницы |

Тема создаётся **при первом комментарии**, а не при просмотре страницы:
иначе каждый заход на каждую страницу писал бы строку в БД, а админка
показывала бы сотни пустых тем.

Если шаблон темы печатает контент не как `page.content`, блок не появится —
тогда в шаблон вставляется вызов:

```twig
{{ community_comments(page) }}
```

Не показывать комментарии на отдельных страницах — настройка
`comments_exclude` (по одному пути в строке).

## Права

| Кто | Читать | Писать | Модерировать |
|---|---|---|---|
| гость | публичные разделы | только комментарии, всегда на проверку | нет |
| пользователь | публичные + свои сообщества | да | нет |
| модератор канала | всё в канале | да | закрепить, закрыть, удалить, одобрить |
| админ сайта | всё | да | всё |

Писать в форум и сообщества могут только зарегистрированные — так на сайте
без штатного модератора не заводится спам-помойка.

## Антиспам

Проверки идут по возрастанию цены, и «подозрительное» не выбрасывается,
а уходит в очередь проверки:

1. скрытое поле (honeypot) — заполнено → отказ;
2. форма заполнена быстрее `min_fill_seconds` — отказ;
3. лимит по хешу адреса: `posts_per_10min` сообщений, `topics_per_hour` тем;
4. больше двух ссылок — на проверку;
5. стоп-слово — отказ;
6. канал с премодерацией или автор-гость — на проверку.

IP не хранится: только `HMAC-SHA256(ip, секрет плагина)`. По хешу можно
отличить «свой» от «чужого» и посчитать частоту, но нельзя восстановить адрес.

## Картинки

В форме есть «Прикрепить картинку». Файл уходит на `/community/upload`,
в текст вставляется markdown-ссылка `![](/storage/uploads/community/...)`.
Тип определяется по содержимому (`getimagesize`), а не по расширению;
разрешены JPG, PNG, WebP, GIF, размер — настройкой `upload_max_mb`.
Каталог `storage/uploads/community/` сайт уже отдаёт, nginx править не нужно.

## Уведомления

Чекбокс «сообщить об ответах письмом» подписывает на тему. При новом
сообщении подписчики получают письмо через почтовые настройки сайта
(админка → Настройки → Почта). Если почта не настроена, отправка просто
не происходит — сообщения при этом сохраняются.

## Админка

- `💬 Сообщество` в меню — очередь «ждут проверки» с кнопками
  «Опубликовать / Спам / Удалить»;
- разделы правятся обычной таблицей ядра:
  `/admin/table/plugin_community_channels`;
- настройки — в карточке плагина.

## Хуки и требования к ядру

| Хук | Зачем |
|---|---|
| `db.migrate` | таблицы и каналы по умолчанию |
| `twig.init` | шаблоны плагина в теме сайта, функции `community_url`, `community_csrf`, `community_comments` |
| `front.router.before` | страницы форума, `/community/reply`, `/community/upload`, `/community/css`, `/community/js` |
| `front.render` | блок комментариев под текстом страницы |
| `front.output` | стили и скрипт |
| `admin.routes`, `admin.menu`, `admin.twig.init`, `admin.current_section` | админка |

**Важно:** обработчик на `front.router.before`, который отдаёт свой ответ,
обязан завершаться `exit`. Иначе управление вернётся в `FrontController`,
и тот дорисует свою 404 поверх — именно так «пропадал» виджет веб-чата.
Плагин делает `exit` и в страницах, и в отдаче статики, и в ответах на 304.

## Стили

`assets/community.css` намеренно нейтрален: фон не задаётся, цвет текста
наследуется от темы, акцент берётся из `--accent-purple`, если тема его
объявляет. Поэтому блок одинаково выглядит на тёмных и светлых шаблонах.

## Этапы

- **1.0** — форум, комментарии к страницам, модерация, антиспам, картинки,
  письма об ответах, админка.
- **2.0** — сообщества: вступление, заявки, модераторы канала, лента.
  Таблица `plugin_community_members` и поля `is_private` / `requires_join`
  уже есть и учитываются при чтении, но интерфейса вступления пока нет:
  закрытый канал сейчас может открыть только админ.
- **3.0** — лайки, жалобы, поиск, RSS, уведомления в MAX/Telegram.

## Схема БД

`plugin_community_channels`, `plugin_community_topics`, `plugin_community_posts`,
`plugin_community_followers`, `plugin_community_members`.
Полная схема — `migrations/001_init.sql`.
