# WebChat — Changelog

## [1.1.2] — 2026-11-27

### Fixed

- **Ответ цитатой не привязывался.** Структуру `link.message.mid` я угадал по
  документации и проверил синтетическим запросом — на живом MAX она другая,
  поэтому цитата не срабатывала, а сообщение спасал только резервный путь
  («последнее сообщение бота»). Теперь mid ищется во всех известных местах,
  а главное — номер обращения берётся **из текста самой цитаты**: в нём уже
  есть `#daristihi-12 · Иван`. Это не зависит от структуры API вообще.
- Диагностика: настройка `debug=1` пишет сырой payload вебхука в
  `storage/logs/webchat-hook.log` — чтобы больше не угадывать формат.

## [1.1.1] — 2026-11-27

### Fixed

- **На мобильном окно чата было не закрыть.** Темы часто задают
  `body > * { position: relative; z-index: 1 }` — контейнер виджета становился
  stacking context, и `z-index` окна внутри него уже ничего не решал: шапка
  сайта (`z-index: 60`) рисовалась поверх. На мобиле окно занимает весь экран,
  и перекрытая шапка прятала заголовок и кнопку закрытия. Теперь у самого
  контейнера `position: relative; z-index: 2147483001 !important` — без
  `!important` не работает: по правилам CSS обычные объявления внешнего дерева
  (тема сайта) побеждают `:host`.
- Найдено на живом сайте (daristihi.ru, 390×844): окно открылось на весь экран,
  но закрыть его было нечем.

## [1.1.0] — 2026-11-27

Один бот на несколько сайтов без перепутанных ответов.

### Added

- **Общий бот.** MAX разрешает несколько вебхуков у одного бота, поэтому
  один и тот же бот может обслуживать все сайты владельца. Плагин определяет
  это сам (`GET /subscriptions` — больше одного адреса) и переключается в
  общий режим. Кеш проверки — 10 минут.
- В общем режиме номер обращения несёт метку сайта: `#daristihi-12` вместо
  `#12`, иначе «#3» совпадает у всех сайтов.
- Ответ без цитаты и без номера в общем режиме маршрутизируется по
  последнему сообщению бота в чате (`GET /messages`): адресат — тот сайт, у
  которого есть mid этого сообщения. Найдётся ровно у одного.
- В админке (`/admin/chats`) — пояснение про общий бот и формат номера.

### Fixed

- **Ответ оператора уходил посетителю чужого сайта.** При общем боте событие
  приходит на вебхук каждого сайта, а правило «последнее активное обращение»
  срабатывало у всех. Теперь в общем режиме этого правила нет: только
  цитата (mid), метка сайта или последнее сообщение бота.
- Нет спама подсказками в общий чат: если сообщение явно относится к другому
  сайту, сайт молчит (подсказка — только когда привязать вообще не к чему).
- В диалоге с ботом `chat_id` не равен `user_id` — плагин запоминает
  настоящий `chat_id` из событий, без него чтение истории не работало.

## [1.0.1] — 2026-11-25

Исправления по итогам первых суток на живом сайте.

### Fixed

- **Виджет «пропадал» через раз.** На повторный запрос скрипта с
  `If-None-Match` обработчик отдавал `304`, но не завершал запрос: управление
  возвращалось во FrontController, тот рисовал 404 и перетирал статус.
  Браузер получал 404 с пустым телом и скрипт не грузил. Теперь `304`
  завершается `exit`. В `init.php` добавлен `onerror`-фолбэк с повторной
  загрузкой на случай разовой сетевой неудачи.
- **Окно чата было открыто при загрузке страницы.** `[hidden]` не срабатывал:
  у панели `display: flex` перебивал браузерный стиль. Добавлено правило
  `[hidden] { display: none !important }`.
- **Цвет и надписи появлялись только после первого сообщения.** Конфиг
  запрашивался лишь при открытии окна, а заголовок подставлялся после ответа
  сервера. Теперь конфиг кешируется в `localStorage` и применяется до первого
  кадра, обновляется при каждой загрузке страницы.
- **Иконка не скрывалась при открытом окне** — теперь скрывается (и
  возвращается при закрытии).
- **Ответ из мессенджера терялся после первого нового обращения.** Ответ без
  номера и без цитаты уходил в «последнее обращение» из настройки
  `last_thread`, а она пишется только при ответе из админки. Теперь берётся
  самое свежее открытое обращение из базы.
- **Молча терялся ответ оператора**, если привязать его было не к чему:
  теперь в мессенджер приходит подсказка, как указать обращение.

### Changed

- Лимиты антиспама подняты (10 новых обращений и 60 сообщений в час/10 минут
  с одного адреса): при отладке на живом сайте срабатывала защита от самого
  владельца. Одинаковые плашки об ошибке больше не дублируются в окне.

### Added

- История диалога переживает перезагрузку страницы и переходы по сайту.
- Индикатор непрочитанных ответов на кнопке (в т.ч. после возврата на сайт).
- `Escape` закрывает окно; кнопка отправки блокируется на время отправки.

## [1.0.0] — 2026-11-25

Первая версия.

### Added

- **Виджет чата** на всех страницах: кнопка в углу, окно, история диалога,
  мобильная вёрстка на весь экран. Скрипт отдаётся маршрутом `/chat/widget`
  (CSS встроен в ответ), поэтому не нужен ни отдельный запрос за стилями,
  ни правка nginx для `*.js`.
- **Канал доставки** — MAX или Telegram, выбирается настройкой:
  - MAX: групповой чат, обращения помечаются номером (`#12 · Иван · /page`),
    ответ привязывается цитатой, префиксом `#12` или уходит в последнее
    активное обращение; `chat_id` подхватывается из события `bot_added`.
  - Telegram: тема форума на каждое обращение, ответ в теме возвращается в виджет.
- **Приём ответов** через вебхук с проверкой секрета (`hash_equals`), по
  заголовкам `X-Max-Bot-Api-Secret` / `X-Telegram-Bot-Api-Secret-Token`.
- **Админка** `/admin/chats`: список обращений с фильтром по статусу и поиском,
  непрочитанные, переписка, ответ из панели, закрытие/переоткрытие, удаление,
  кнопка «Проверить подключение» (подписывает вебхук и шлёт тестовое сообщение).
- **Антиспам**: лимиты на обращения и сообщения с одного адреса (файловые
  счётчики с окном), ограничение длины сообщения, IP хранится только как хеш.
- Пункт меню «Чаты» с числом непрочитанных обращений.
