# NPD — чеки самозанятого

Плагин для [apidcms](https://apidcms.ru): после оплаты регистрирует доход в сервисе
ФНС «Мой налог» (`lknpd.nalog.ru`) и отдаёт покупателю ссылку на чек.

## Зачем

По 422-ФЗ самозанятый обязан сформировать чек и передать его покупателю в момент
расчёта. ЮKassa этого не делает: «Отправка чеков в налоговую» для самозанятых
недоступна, чек нужно пробивать вручную в приложении «Мой налог». На потоке
оплат это нереально и приводит к штрафам.

## Что делает

- Слушает `payments.confirmed` (его рассылает плагин `yookassa`) и ставит чек
  в очередь — таблица `plugin_npd_receipts`, одна строка на платёж.
- Регистрирует доход: `POST /api/v1/income` → `approvedReceiptUuid` + ссылка на чек.
- Отдаёт ссылку покупателю: страница `/receipts` в личном кабинете сайта и,
  если включено, письмо.
- Для ботов и ручных продаж — `POST /npd/income` с HMAC-подписью: ссылка
  возвращается прямо в ответе, чтобы отдать её вместе с результатом заказа.
- Журнал в админке (`/admin/npd`): статус, ошибка, повтор, аннулирование.

## Установка

1. Скопировать папку `npd/` в `plugins/`.
2. Создать ключ шифрования токенов (один раз, на сервере):

   ```bash
   php plugins/npd/tools/make-key.php
   ```

3. Админка → Плагины → **NPD** → включить плагин.
4. Админка → **Чеки НПД** → войти по SMS (телефон из приложения «Мой налог»).
   Пароль не нужен: плагин его не спрашивает и не хранит.
5. Проверить связь кнопкой «Проверить связь».
6. В настройках плагина снять галочку «Пробный режим» — только после проверки.
7. Cron (по желанию, но желательно):

   ```
   */5 * * * * curl -s "https://site.ru/npd/tick?key=КЛЮЧ" >/dev/null
   ```

   Ключ показан в админке. Без cron очередь добирается ленивым тиком после
   ответа на запросы посетителей, но cron надёжнее.

## Безопасность

| Что | Как |
|---|---|
| Пароль ЛК физлица | **не хранится вообще** — вход только по SMS-коду |
| Токены ФНС | AES-256-GCM, ключ в `config/npd.php` (вне базы и вне git) |
| Повторный чек | уникальный индекс по `payment_id` + статусная машина |
| Сбой ФНС | очередь с повторами (5 попыток), ошибка видна в журнале |
| Письма | ссылка на чек, никаких реквизитов |

## Настройки

| Ключ | Что |
|---|---|
| `enabled` | пробивать чеки |
| `dry_run` | пробный режим: в ФНС не отправляем (по умолчанию **включён**) |
| `service_name` | наименование услуги в чеке, подстановки `{description}`, `{ref}`, `{id}` |
| `payment_type` | способ расчёта: `CASH` (карта и наличные — расчёт в момент оплаты) или `WIRE` (перевод по счёту). Других ФНС не принимает |
| `default_income_type` | плательщик по умолчанию: физлицо / организация |
| `send_email` | отправлять письмо со ссылкой на чек |
| `notify_email` | куда писать о сбоях |

## Хуки

Экшен `payments.confirmed` — постановка в очередь. Своих хуков наружу не
публикует; для интеграции используется HTTP-эндпоинт.

## Ограничения

- API `lknpd.nalog.ru` **неофициальный** (тот же, что у веб-кабинета). ФНС может
  изменить его без предупреждения — весь доступ собран в `src/Nalog.php`.
- Лимит НПД 2,4 млн ₽ в год: при превышении чеки перестанут проходить,
  в журнале будет понятная ошибка.
- Возвраты: чек аннулируется кнопкой в журнале (причина из списка ФНС:
  возврат денег / чек ошибочный / сбой) или вручную в ЛК налоговой.
- Проверено живыми запросами 26.11.2026: `paymentType` принимает только
  `CASH` и `WIRE` (значение `ACCOUNT` отклоняется), отмена — через
  `/api/v1/cancel` с обязательным `requestTime`. Незнакомые значения плагин
  приводит к допустимым и пишет в лог, а не роняет чек.
