# Changelog — SEO

## 0.1.5 — 2026-11-26

### Исправлено

- **В отчёт попадали блоки контента как отдельные страницы.** Плагин считал
  записями любые таблицы из навигации, включая `landing`, `about`, `price`,
  `faq`, `reviews`, `form` — это контент одной страницы, у него нет своих
  адресов. В отчёте появлялись выдуманные URL вида `/glavnaya/35`, `/faq/6`,
  `/price/1`, которые отдают 404: на `prostostihi.ru` из 193 «страниц» 95 были
  такими, на `wearefun.ru` — 51 из 57.

  Теперь записями раскрываются только разделы с `page_type = dynamic` — ровно
  те, для которых ядро строит адреса `/раздел/запись`
  (`FrontController::handleDynamicContent`). То же правило применено к карте
  сайта и к поиску документа по адресу.

- **Разделы-лендинги выпадали из отчёта.** Главная страница сайта, где раздел
  «/» — это `landing` (а не привязанная страница), не попадала в список вообще:
  фильтр пускал только `dynamic/blog/catalog/search/form/ai`. Теперь в отчёт
  входит любой раздел, кроме `raw`/`external` (машиночитаемые файлы и чужие
  страницы) и `search`/`ai` (нет своего контента).

### Добавлено

- `tools/urls.php` — печатает все адреса, которые плагин считает документами
  сайта. Проверка «каждый адрес открывается» на живом сайте ловит выдуманные
  URL и битые страницы до того, как они уедут в sitemap.

## 0.1.4 — 2026-11-26

### Исправлено

- **Главная страница не находилась** на сайтах, где раздел «/» — это landing
  без привязанной страницы (`navigation.page_id` пустой), а `pages.slug`
  равен `/`. Плагин не мог определить документ и выводил только `robots`:
  без `canonical`, Open Graph и JSON-LD. Обнаружено на `wearefun.ru`.

- **Мультиязычные поля уезжали в `<title>` сырым JSON.** В базе `title` и
  `description` могут лежать как `{"ru":"…","en":"…"}`; теперь они
  разворачиваются через `Core\I18n` по локали запроса. Обнаружено на `nldb.ru`.

- Текст landing-разделов теперь собирается из их `source_table`, а не считается
  пустым: анализатор видел ноль слов там, где контент есть.

### Добавлено

- `tools/probe.php` — проверка «какой документ плагин видит по этому адресу»
  на реальной базе сайта, без запуска CMS. Ловит такие расхождения до деплоя.

## 0.1.3 — 2026-11-26

### Исправлено

- **Плагин затирал хорошие теги темы.** Приоритет источников был
  «SEO-поле → контент → тема», и на живом сайте `daristihi.ru` это заменило
  вручную прописанные `<title>` и `og:title` («Дари! — стихи, открытки и песни
  на заказ») техническим значением из `pages.title` — «Main».

  Теперь порядок правильный: **SEO-поле → то, что уже выводит тема → колонка
  контента**. Колонка `title` в базе часто содержит служебную подпись для
  админки, а тема выводит осмысленный текст — плагин не должен его трогать.
  Правило действует для `title`, `description`, `og:title`, `og:description`,
  `og:image`, `canonical` и `robots`.

- Плагин теперь читает из HTML темы все теги (`og:*`, `canonical`, `robots`),
  а не только `title` и `description`, и сохраняет их как второй приоритет.

### Добавлено

- Самотест проверяет приоритет источников (9 проверок): тема важнее контента,
  SEO-поле важнее темы, без темы берётся контент. Всего 27 проверок.

## 0.1.2 — 2026-11-26

### Исправлено

- **Стили не работали.** `admin.css` ядра — собранный (purged) Tailwind: в нём
  есть только классы, которые используют шаблоны ядра. Из ~210 классов плагина
  в файле отсутствовали 103, в том числе `bg-indigo-600` и `text-indigo-900` —
  кнопка «Всё сразу» была белым текстом на прозрачном фоне, а текст в блоке
  предложения наезжал друг на друга. Плагин переведён на собственный CSS с
  семантическими классами (`views/_styles.twig`, префикс `.seo-`): вид больше
  не зависит от пересборки Tailwind в ядре.
- **Иконки были пустыми квадратами.** Font Awesome подключается в админке
  ядра с cdnjs, и шрифт (woff2/ttf) реально не загружается: запросы падают с
  `net::ERR_FAILED` при том, что CSS отдаётся с кодом 200. Плагин переведён на
  инлайн-SVG (`views/_icons.twig`) — рисуется всегда, без сети.

### Изменено

- **Счётчик длины показывает то, что реально уйдёт на сайт.** Пустое поле —
  не «0 символов» красным, а «49 (из контента)» серым: раньше это выглядело
  как противоречие с чек-листом «описание задано».
- Плейсхолдеры полей показывают работающее значение из контента.
- В обзоре колонка «Описание» показывает эффективное значение с пометкой
  «из контента» вместо красного «пусто»; у страниц со своим SEO-заголовком
  появилась метка «свой заголовок».

## 0.1.1 — 2026-11-26

### Исправлено

- **Кнопка генерации была одна и стояла под полем «Описание»** — выглядело как
  кнопка для описания, а при заполненных полях молча ничего не делала и всё равно
  писала «Готово». Теперь кнопка есть у каждого поля, результат показывается
  предложением с «Применить / Отменить»: ничего не перезаписывается молча.

### Добавлено

- Панель «Заполнить нейросетью» вверху редактора: «Всё сразу», «Заголовок»,
  «Описание», «Ключевые фразы» — видна сразу, не спрятана в поле.
- Отдельные промты на каждое поле: короче ответ, точнее результат, меньше токенов.
- Ключевые фразы приходят тремя вариантами — выбор кликом.
- Кнопка-«искра» у заголовка, описания и ключевой фразы.

## 0.1.0 — 2026-11-26

Первая версия плагина.

### Добавлено

- **Мета-теги на сайте**: `title`, `description`, `robots`, `canonical`,
  Open Graph, Twitter Card и JSON-LD (`WebSite`, `BreadcrumbList`, `Article`).
  Теги вставляются в готовый HTML, тема ничего менять не должна; для тем,
  которым нужен контроль, есть `{{ seo_meta() }}`.
- **SEO-поля для любой сущности** в отдельной таблице `plugin_seo_meta`
  (страницы, записи таблиц, разделы): схема ядра не меняется, миграция не нужна.
- **Советник**: оценка 0–100 по чек-листу из 20+ пунктов (заголовок, описание,
  объём, H1, ключевая фраза и её плотность, alt, внутренние ссылки, адрес,
  картинка для соцсетей, noindex, канон). Анализ офлайновый — без сети и токенов.
- **Карта сайта** `/sitemap.xml` из страниц, разделов и записей; `noindex`-страницы
  и адреса с редиректом в карту не попадают. Кэш на час, кнопка пересборки.
- **robots.txt** в режиме «авто»: отдаётся только когда своей страницы robots.txt
  в навигации нет.
- **301-редиректы** с счётчиком срабатываний и **журнал 404** с подсказкой
  ближайшего существующего адреса.
- **Генерация заголовка и описания** нейросетью через ключ DeepSeek из настроек CMS.
- Пункт меню с числом страниц, у которых оценка ниже 55.
