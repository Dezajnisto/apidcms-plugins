# WebChat — веб-чат с ответами из мессенджера

Чат-виджет для сайта: посетитель пишет в окно на странице, владелец сайта
отвечает из **MAX** или **Telegram** — панель оператора держать открытой не
нужно. Всё остальное время обращения лежат в админке (`/admin/chats`),
история хранится в базе сайта.

Плагин рассчитан на одного-двух человек в поддержке, а не на колл-центр:
никаких отделов, SLA и ролей — только «пришло сообщение → пришёл ответ».

## Что умеет

- Виджет на всех страницах сайта: кнопка в углу, окно чата, история диалога в браузере
- Ответы из **MAX** (Россия, без VPN) или **Telegram** — канал выбирается в настройках
- Переписка в админке: список обращений, непрочитанные, поиск, ответ из панели
- Имя, страница и referrer посетителя — видно, откуда пришёл и что смотрел
- Антиспам: лимиты на число обращений и сообщений с одного адреса, ограничение длины
- Ничего не грузится, пока посетитель не открыл чат: один скрипт (~11 КБ) и запрос конфига по клику

## Установка

1. Скопируйте каталог `webchat` в `public_html/plugins/` вашего сайта.
2. В админке: **Плагины → WebChat → включить**.
3. Заполните настройки канала (ниже) и нажмите **«Проверить подключение»** на
   странице «Чаты» — плагин сам подпишет вебхук и отправит тестовое сообщение.
4. Виджет появляется на всех страницах сразу после включения.

Требования: PHP 8.0+, ext-curl, SQLite (штатная база apidcms), HTTPS для вебхука.

## MAX

1. Заведите бота на [business.max.ru](https://business.max.ru/self) → **Чат-боты**,
   скопируйте токен в настройку «MAX: токен бота».
2. Нажмите на странице «Чаты» кнопку **«Проверить подключение»** — плагин
   подпишет вебхук. ID получателя можно не заполнять.
3. Напишите боту любое слово в MAX (в личку) — плагин запомнит, куда присылать
   обращения. Для группы: добавьте бота в групповой чат, событие `bot_added`
   тоже сохранит ID автоматически.

> **Сертификат Минцифры.** MAX отдаёт TLS-сертификат, которого нет в стандартном
> наборе корневых сертификатов. Плагин носит его с собой
> (`assets/ca/russian_trusted.pem`) и при ошибке TLS повторяет запрос с ним —
> ставить что-то в систему не нужно. Если хочется по-другому: положите этот
> файл в системный набор (`update-ca-certificates`) и он просто не понадобится.

**Как отвечать.** MAX не умеет темы, поэтому у каждого обращения есть номер:

```
#12 · Иван
https://site.ru/catalog/palatka
———
А есть размер 42?
```

- ответьте **цитатой** на это сообщение — ответ уйдёт Ивану;
- либо начните текст с `#12 ` — тоже уйдёт Ивану;
- либо просто напишите текст — уйдёт в **последнее активное** обращение.

## Один бот на несколько сайтов

Если один и тот же бот обслуживает несколько сайтов, плагин определяет это
сам: у бота больше одного адреса в `GET /subscriptions`. Переключать ничего
не нужно — но меняются правила адресации ответа:

| Что | Один сайт | Несколько сайтов |
|---|---|---|
| Номер обращения | `#12 · Иван` | `#daristihi-12 · Иван` (метка из домена) |
| Ответ цитатой | работает | работает |
| Ответ с номером | `#12 текст` | `#daristihi-12 текст` |
| Ответ без цитаты | последнее активное обращение | тот сайт, чьё сообщение бота в чате последнее |

Почему так: MAX разрешает несколько вебхуков у одного бота, и событие
приходит на вебхук **каждого** сайта. Без этих правил ответ оператора попал бы
посетителю другого сайта — у каждого сайта свой «#3» и своё «последнее
обращение». Определение общего режима кешируется на 10 минут.

Для Telegram общий бот **технически возможен, но иначе**: у бота только один
вебхук (`setWebhook` перезаписывает предыдущий), поэтому нельзя, чтобы каждый
сайт слушал свой адрес. Второй сайт с тем же токеном просто **отберёт события
у первого** — молча. Плагин этого не делает и не проверяет.

Если понадобится общий бот в Telegram, нужен один «узел»: единственный
вебхук на одном сайте, который пересылает событие остальным (маршрут — по
`message_thread_id`, потому что темы уже привязаны к обращениям). Это отдельная
работа, в 1.1.x её нет.

У MAX такого ограничения нет: несколько вебхуков у одного бота разрешены
(`GET /subscriptions` возвращает массив), поэтому там общий бот работает
«из коробки».

## Telegram

1. `@BotFather` → `/newbot` → токен в настройку «Telegram: токен бота».
2. Группа с включёнными **темами** (форум), бота — в группу.
3. ID группы (вида `-1001234567890`) — в настройку «Telegram: ID группы».

На каждого посетителя плагин создаёт отдельную тему (`#12 · Иван · /catalog`),
ответ в теме возвращается в виджет. Если темы в группе выключены, плагин
работает как с MAX — по номеру в тексте и последнему обращению.

## Поведение виджета

- Кнопка в углу; при открытии окна кнопка **скрывается**, при закрытии возвращается.
  `Escape` закрывает окно.
- Заголовок, приветствие и цвет берутся из настроек и видны **сразу** — конфиг
  кешируется в браузере и обновляется при каждой загрузке страницы.
- История диалога переживает перезагрузку страницы и переходы по сайту.
- Если оператор ответил, пока посетитель ходил по другим страницам, на кнопке
  появляется счётчик непрочитанных.
- Опрос новых сообщений идёт только при открытом окне (раз в 3 секунды).

## Маршруты

| Путь | Что делает |
|---|---|
| `GET /chat/widget` | скрипт виджета (CSS встроен в ответ, без второго запроса) |
| `GET /chat/api/config` | заголовок, приветствие, цвет, «на связи» |
| `POST /chat/api/start` | создать обращение → токен посетителя |
| `POST /chat/api/send` | сообщение посетителя |
| `GET /chat/api/poll?token=…&after=…` | новые сообщения (короткий опрос раз в 3 с) |
| `POST /chat/api/hook/max` | вебхук MAX (заголовок `X-Max-Bot-Api-Secret`) |
| `POST /chat/api/hook/telegram` | вебхук Telegram (`X-Telegram-Bot-Api-Secret-Token`) |
| `/admin/chats` | обращения, ответ, проверка подключения |

Маршруты не требуют правки nginx: всё под `/chat/` отдаёт PHP. Скрипт виджета
намеренно без расширения `.js` — иначе стандартное правило
`location ~* \.(css|js)$` отдаёт такие адреса статикой и PHP до них не доходит.

⚠️ Обработчик, который отвечает сам (как `/chat/widget`), обязан вызывать
`exit`. Если вернуть управление в `FrontController`, он нарисует свою 404 и
перетрёт статус: ответ `304 Not Modified` превращается в `404` с пустым телом,
и браузер молча не загружает скрипт. На этом виджет уже «пропадал через раз».

## Настройки

| Ключ | Что это |
|---|---|
| `channel` | `max` или `telegram` — куда присылать обращения |
| `online` | принимать обращения; выключено — посетитель видит текст «не в сети» |
| `title`, `greeting`, `offline_text` | тексты окна чата |
| `color`, `position` | цвет акцентов (HEX) и сторона кнопки |
| `max_token`, `max_chat_id` | бот и чат MAX |
| `tg_token`, `tg_chat_id` | бот и группа Telegram |

Секреты (токены, секрет вебхука) хранятся в таблице `plugin_settings`, не в
`plugin.json`, и не выводятся обратно в HTML.

## Таблицы

- `plugin_webchat_threads` — обращения: токен посетителя, страница, referrer,
  браузер, хеш IP, статус, счётчик непрочитанных, внешняя ссылка (тема Telegram)
- `plugin_webchat_messages` — сообщения: направление `in`/`out`, текст, автор,
  ID сообщения в мессенджере (для ответа цитатой)

## Приватность

- IP не хранится: только необратимый хеш (антиспам).
- Имя и контакт посетителя пишутся, только если он сам их оставил.
- Переписка остаётся в базе вашего сайта; в мессенджер уходит текст сообщения.

## Проверка без реального бота

Для локальных тестов адрес Bot API можно подменить: значение
`api_base` в `plugin_settings` (в настройках его нет — служебное).
Удобно, когда надо проверить поток сообщений без токена:

```sql
INSERT INTO plugin_settings (plugin, setting_key, setting_value)
VALUES ('webchat', 'api_base', 'http://127.0.0.1:8099')
ON CONFLICT(plugin, setting_key) DO UPDATE SET setting_value = excluded.setting_value;
```

После теста запись нужно удалить, иначе плагин продолжит ходить на мок.
